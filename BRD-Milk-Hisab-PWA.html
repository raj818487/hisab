1. Purpose & Vision

Build a small, easy-to-use website application that helps a household or small milk business track daily milk taken / not taken, calculate monthly payable amount (hisab), save everything in a database, and use a clean UI for day-to-day entry.

The app must be installable like a mobile app using a Web App Manifest (PWA), so it can open from the home screen, work reliably on phone, and optionally support offline entry.

Vision one-liner: “Mark milk each day in 2 taps → get clear monthly hisab with payments, history, and reminders.”

2. Problem Statement

Today, milk delivery hisab is often done on paper, WhatsApp notes, or memory. That causes:

  • Missed days not recorded correctly (took / not took confusion)
  • Wrong monthly total when rate or quantity changes mid-month
  • No clear record of advance / partial payments
  • Hard to share clean monthly bill with customer or supplier
  • No history for previous months

The product must replace paper hisab with a simple digital system that is still faster than writing by hand.

3. Goals & Success Criteria

Business goals

  • Accurate daily tracking of milk delivery / consumption
  • Automatic monthly payable calculation
  • Payment recording and due balance visibility
  • Usable by non-technical users on mobile

Success criteria (MVP)

  • User can create customer/supplier and set default daily qty + rate
  • User can mark each calendar day as Taken / Not Taken (with optional qty override)
  • System calculates month total correctly
  • User can record payment and see remaining due
  • App installs via manifest (Add to Home Screen) on Android Chrome
  • All entries persist in database and survive refresh/reopen

5. Scope

In scope (MVP + recommended extras)

  • Customer/supplier master
  • Daily delivery log (taken / not taken, quantity, rate, notes)
  • Monthly hisab summary and statement
  • Payments (advance, partial, full)

6. Functional Requirements (Features)

6.1 Core — Daily Milk Log

  • FR-01 Show month calendar for selected customer
  • FR-02 Tap a day to mark Taken or Not Taken
  • FR-03 On Taken: default quantity & rate auto-fill; user can override for that day
  • FR-04 Support morning / evening slots (optional toggle in settings)
  • FR-05 Add note per day (e.g., “guest home”, “sour milk returned”)
  • FR-06 Bulk mark date range (e.g., whole week Taken)
  • FR-07 Prevent future dates beyond today (configurable)

6.2 Core — Monthly Hisab

  • FR-08 Auto calculate: Total Qty, Total Amount, Days Taken, Days Skipped
  • FR-09 Apply adjustments: extra charge, discount, previous due carry-forward
  • FR-10 Show Payable = Opening Due + Month Amount + Adjustments − Payments
  • FR-11 Close / lock month after final hisab (optional) to avoid accidental edits
  • FR-12 Generate shareable monthly statement

6.3 Payments

  • FR-13 Record payment with date, amount, mode (Cash / UPI / Bank), reference note
  • FR-14 Support advance payment before month end
  • FR-15 Show running balance after each payment
  • FR-16 Payment history list per customer

6.4 Masters

  • FR-17 Customer master: name, phone, address, default qty, default rate, active flag
  • FR-18 Rate history: if rate changes mid-month, old days keep old rate (or apply from effective date)
  • FR-19 Holiday / off-day templates (e.g., every Sunday auto Not Taken — optional)

6.5 Additional Features (to make app more than “easy only”)

  • FR-20 Dashboard: today’s pending marks, unpaid months, top dues
  • FR-21 Reminders: notify owner for unmarked yesterday; remind unpaid hisab
  • FR-22 WhatsApp share: one-tap share monthly bill text/PDF
  • FR-23 PDF / CSV export: monthly statement download
  • FR-24 Multi-customer: manage many households / routes
  • FR-25 Products beyond milk: curd, ghee line items (simple product list)
  • FR-26 Offline PWA mode: mark days offline, sync when online
  • FR-27 Backup / restore: export full data JSON/CSV
  • FR-28 PIN lock: simple app lock on open
  • FR-29 Audit trail: who changed a day entry (if multi-user later)
  • FR-30 Charts: monthly qty trend, payment collection chart

7. Monthly Hisab Rules (Business Logic)

Default calculation for one customer in one month:

  1. For each day marked Taken: day_amount = quantity × rate
  2. month_amount = sum(day_amount)
  3. gross_payable = opening_due + month_amount + extra_charges − discounts
  4. net_due = gross_payable − sum(payments in period)
ExampleValue
Default qty1.5 litre / day
Rate₹60 / litre
Days taken in month26
Month amount26 × 1.5 × 60 = ₹2,340
Previous due₹200
Payment received₹2,000
Closing due₹540
If quantity/rate changes on specific days, use that day’s override values, not only the customer default.

8. Non-Functional Requirements

  • Usability: daily mark must be possible in under 5 seconds on phone
  • Performance: month calendar load < 2 seconds for 31 days × typical customers
  • Reliability: no data loss on refresh; DB is source of truth
  • Security: authenticated API; no open write endpoints; PIN/password for app
  • Availability: PWA usable on mobile browser; installable
  • Backup: export option mandatory before production use

9. PWA / Manifest Requirements (“menifiest”)

User requested a website using manifest and related web-app capabilities. Requirements:

  • FR-PWA-01 Provide manifest.webmanifest with name, short_name, icons, theme/background color, display: standalone, start_url
  • FR-PWA-02 App icons (192px, 512px) for Add to Home Screen
  • FR-PWA-03 Service worker for caching shell (HTML/CSS/JS)
  • FR-PWA-04 Offline queue for daily marks when network is unavailable (Phase 2)
  • FR-PWA-05 HTTPS hosting required for installability
Result: user can install “Milk Hisab” like an app icon on phone, open fullscreen without browser chrome.

12. Tech Approach (Recommended)

Keep it small but solid:

LayerRecommendationWhy
Frontend Angular or simple HTML/JS PWA Fast UI, easy mobile layout; matches your existing Angular skill if desired
Backend API .NET Web API or Node Clean CRUD + auth
Database PostgreSQL (or SQLite for ultra-local MVP) Reliable persistence
PWA manifest + service worker Installable app experience
Hosting Vercel/Netlify (UI) + small API host + managed DB Low cost for personal/small business use
If you want fastest MVP: one .NET API + Angular (or even static HTML) + Postgres, then add offline sync later.

14. Assumptions, Risks, Open Questions

Assumptions

  • Primary users are comfortable with smartphone Chrome/Safari
  • Currency is INR unless configured otherwise
  • One owner manages entries in MVP

Risks

  • Users forget to mark days → need reminders + easy backfill
  • Mid-month rate change confusion → need clear effective-date rule
  • Offline edits conflict → need simple last-write or sync rules in Phase 3

Open questions (need your decision)

  1. Is this for home consumption (you buy milk) or dairy seller (you deliver to many customers)?
  2. One delivery per day, or morning + evening?
  3. Should skipped days be auto-assumed if not marked, or must every day be marked?
  4. Do you need Hindi UI labels in v1?
  5. Preferred stack: Angular + .NET (like your LIMS style) or lighter HTML/JS + SQLite?

15. Acceptance Criteria (MVP Sign-off)

  • Given a customer with default 1L @ ₹60, when 20 days are Taken, month amount shows ₹1,200
  • When a day is marked Not Taken, it does not add amount
  • When payment of ₹500 is added, due reduces by ₹500
  • After browser refresh, all data remains (DB persistence verified)
  • Manifest allows “Install app” / Add to Home Screen on Android Chrome
  • Monthly statement can be viewed and exported
