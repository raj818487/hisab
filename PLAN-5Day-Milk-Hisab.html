1. Goal & Definition of Done (Day 5 evening)

By end of Day 5, a working installable product exists where a user can:

  • Add customers with default qty + rate
  • Mark each day Taken / Not Taken (qty/rate override + note)
  • See monthly qty, amount, payments, and due balance
  • Record payments (cash/UPI)
  • Export/share monthly statement
  • Install app via PWA manifest on phone
  • Data saved in real DB and survives refresh
Full product in 5 days means MVP + high-value extras (dashboard, export, share text, reminders light, backup). Deep offline sync / multi-user audit can be “stretch” if time remains.

5. Day 1 — Foundation (Tooling, Schema, Shell)

Morning (3–4h) — Setup

  • Run install.ps1 + connect.ps1 from/for Milk-Hisab (skills + graphify wiring)
  • Create solution structure:
    • backend/ .NET Web API
    • frontend/ Angular app with PWA schematic
    • docs/ keep BRD + this plan
  • Use grill-me + BRD to lock: home-use vs multi-customer seller mode (default: multi-customer ready, start with 1–N customers)
  • Use db-design skill: finalize tables users, customers, daily_entries, payments, month_closings

Afternoon (4–5h) — Skeleton working

  • EF Core migrations + seed admin/PIN user
  • API health endpoint + CORS
  • Angular shell: layout, routing stubs (Dashboard, Customers, Daily, Hisab, Payments, Settings)
  • Add manifest.webmanifest + icons placeholders + basic service worker
  • Commit: “Day1 foundation”

Day 1 Done when: API runs, UI opens, DB migrates, PWA manifest validates, skills installed.

6. Day 2 — Customers + Daily Entry (Core Loop)

Morning

  • Customers API: list/create/update/status
  • Customers UI: table + dialog (name, phone, default qty, default rate)
  • Clone patterns via pattern-clone (keep UI consistent)

Afternoon

  • Daily entries API: get month grid, upsert day (taken/skipped, qty, rate, note)
  • Daily Calendar UI: month navigator, color states, day editor sheet
  • Validation: no negative qty; skipped clears amount; overrides allowed
  • Quick action: “Mark today Taken” from dashboard stub

Day 2 Done when: you can create a customer and mark days; refresh keeps data.

7. Day 3 — Monthly Hisab + Payments (Money Truth)

Morning

  • Hisab compute endpoint: days taken, total qty, month amount, opening due, adjustments
  • Hisab UI: month summary cards + day breakdown table
  • Business rules from BRD implemented exactly

Afternoon

  • Payments API + UI (amount, date, mode, note)
  • Net due = opening + month + extras − discounts − payments
  • Optional month lock (close month)
  • Unit/integration tests for calculation edge cases (test-agent)

Day 3 Done when: sample month math matches BRD example; payments reduce due correctly.

8. Day 4 — PWA Product Feel + Extras

Morning

  • Polish PWA: real icons, theme color, standalone display, install prompt notes
  • Dashboard: pending marks, unpaid dues, quick mark
  • Settings: morning/evening slot toggle (if enabled), PIN lock basic

Afternoon

  • Export monthly statement CSV + printable PDF/HTML
  • WhatsApp share text generator (copy/share sheet)
  • Backup export JSON
  • Light reminders: banner if yesterday unmarked
  • Run code-review-quality + fix critical issues

Day 4 Done when: app is installable on Android Chrome and statement can be shared/exported.

9. Day 5 — Hardening, QA, Launch

Morning

  • End-to-end test script (manual + automated smoke)
  • Fix bugs from Day 2–4
  • Seed demo data for showcase
  • Security pass: auth on all write APIs, no open DB

Afternoon

  • README: how to run, how to install PWA, how hisab works
  • Update graphify (graphify extract . --code-only)
  • Release build (frontend prod + API publish)
  • Stretch if time: second product line (curd) OR offline queue v1
  • Final demo checklist walkthrough

Day 5 Done when: fresh machine can run app, install PWA, complete one full month hisab flow without errors.

11. Risks & buffers

  • Scope creep: if behind after Day 2, freeze extras (charts, multi-product, deep offline)
  • Hisab disputes: keep day-level audit fields (updatedAt) even in MVP
  • PWA HTTPS: local can use localhost; phone install needs LAN HTTPS or deployed URL
  • Buffer: keep 20% of Day 5 only for bugfix — do not start new features after Day 5 noon
